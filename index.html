背景与目标

Dino English 面向海外多业务线（韩国 / 沙特 / 马来 / 越南 等）开展投放与运营。当前业务依赖人工散表查询用户与订单、线索靠线下导表分配，Facebook Lead Form 数据也无法实时进入 Dino English 与 CRM；销售在谈单时难以快速获取用户学习情况与完整订单流水。CRM 一期先把「用户、订单查得到、看得清」做扎实；二期把线下导表的线索分配 / 跟进收进销售中心并接入外呼；三期补齐用户上课记录、报告、回放、清晰的主子订单流水，并将 Facebook Lead Form 自动同步、自动注册后纳入销售闭环，提升销售谈单效率。

一期价值

  • 用户 / 订单一处可查，替代散表
  • 用户按渠道来源（落地页 / App 三方归因）+ 国家粗归因
  • 运营 / 销售按多条件秒级定位用户/订单

二期价值

  • 注册线索自动沉淀销售中心、分配 / 跟进闭环
  • 接入外呼：点号码拨打 + 通话录音 + AI 通话小结自动归档
  • 销售组长按权重自动分配、超时掉库、重新分配
  • 角色权限（RBAC 子权限）+ 数据隔离 + 操作日志

三 / 四 / 五期价值

  • 销售可快速查看用户学习信息与完整订单流水
  • 渠道结构标准化、可生成投放 code
  • SKU 自助上下架 + 优惠券配置 + 落地页一键投放
  • 本地化配置自助；push 暂考虑通过第三方平台承载

产品定位详述

平台不是一个孤立的「查询工具」，而是随业务成熟度逐层演进的运营中台：先把分散在各处的运营数据收拢为「单一事实来源」，再把商业化配置能力交还运营，最终以用户为中心做精细化触达与服务。其价值主线始终围绕「降低对研发的依赖、提升一线自助效率、让运营动作可归因可衡量」。

是什么

  • 海外多业务线的运营中台
  • 用户 / 渠道 / 商品主数据中心
  • 运营动作的统一操作台

解决什么

  • 散表查询、口径不统一
  • 归因断链、促销依赖研发
  • 触达与服务无抓手、难闭环

不做什么（边界）

  • 不替代 App / 学习产品本身
  • 不做面向 C 端用户的前台
  • 初期不做复杂 BI / 数仓（对接为主）

未付费-体验中已注册、未付费，体验课进行中无付费订单 且 有「进行中」体验课 且 无「已完课」体验课
未付费-已体验已注册、未付费，但已完课过体验课无付费订单 且 有「已完课」体验课
付费付费正式商品包，且在有效期内（可能首次付费，也可能到期后自动订阅）持有正式包 且 当前时间 ≤ 有效期
付费逾期付费正式商品包，已过有效期且未续订曾持有正式包 且 当前时间 > 有效期 且 未续订
🔄
状态为系统自动流转、不可手工编辑：由是否有付费订单 + 体验课完课情况联合判定；正式包到期后自动订阅成功仍为「付费」，到期未续订则转为「付费逾期」；「未付费-未体验 + 有手机号」用户由销售中心跟进闭环。
