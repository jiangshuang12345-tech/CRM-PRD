# Dino English 运营平台（CRM）· 迭代计划 + 交互式 PRD

基于「CRM 与运营平台需求对齐」会议纪要与最新迭代计划整理的**分期迭代计划**与**可交互 PRD**。文档按业务诉求分五期落地，并内嵌真实在线原型可逐模块体验。

> **最新迭代状态：** 一期（用户 / 订单基础查询）已于 **7 月 23 日验收完成并投入使用**；二期短期替代方案（越南站外呼与数据打通）已于 **7 月 30 日上线**；二期（销售 leads、外呼、角色权限）计划于 **8 月 18 日上线**。二期原型中的工时估算相关内容已隐藏。

## 产品定位

**一句话定位：** Dino English 运营平台（CRM）是面向海外多业务线的**一体化运营中台**——以「用户 · 渠道 · 商品」三大主数据为核心，打通「渠道归因 → 商品/促销配置 → 投放落地 → 用户触达 → 服务履约」的运营闭环，让市场、运营、客服等**非研发角色自助完成日常运营**，把对研发的依赖降到最低。

随业务成熟度五阶段演进：

| 阶段 | 定位关键词 | 核心能力 | 主要服务对象 |
| --- | --- | --- | --- |
| 一期（已完成） | 数据可查 · **看得清** | 用户中心、订单中心、多语言；**7 月 23 日验收完成并投入使用** | 运营 · 销售 |
| 二期短期替代（已上线） | 越南站过渡 · **先跑通** | 借道国际化 1V1 完成越南站外呼与数据打通；**7 月 30 日上线** | 越南站销售 · 运营 |
| 二期（计划上线） | 销售 leads · **够得着** | 销售中心（分配 leads / 跟进 leads + 外呼）与角色权限；**计划 8 月 18 日上线** | 销售 · 客服 · 管理员 |
| 三期（需求中） | 配置化运营 · **交还业务** | 将配置化工作交还业务运营，缩短流程、减少沟通时间并释放研发资源 | 运营 · 市场投放 |
| 四期 | 用户与订单运营 · **可导出、可触达** | 用户列表、订单列表下载（新增权限）；用户标签体系、push 配置、用户详情、订单详情 | 运营 · 客服 · 管理员 |
| 五期 | 本地化自助 · **改得动** | 本地化配置 | 运营 · 本地化 |

## 目标用户（内部 B 端角色）

> **当前使用方（暂定）：运营 + 销售。** 一期主要由运营与销售使用（用户中心 / 订单中心查询）；下表为平台完整角色画像，其余为后续 / 潜在角色，随能力上线逐步引入。

| 角色 | 核心诉求 | 高频模块 |
| --- | --- | --- |
| 🛠️ 运营 / 商业化 `当前` | 快速查到用户/订单、看清状态与有效期；三期商品/促销自助配置、不依赖研发；后期触达与服务编排 | 用户中心 · 订单中心 ·（三期）商品包/优惠券/落地页 ·（后期）触达/服务节点 |
| 💼 销售 / 业务跟进 `当前` | 查到用户与订单、看清付费状态与有效期；二期在销售中心领取「未付费-未体验+有手机号」线索并记录跟进 / 外呼、促成付费；销售组长可配置自动分配/掉库、重新分配 | 用户中心 · 订单中心 ·（二期）销售中心（分配/跟进 leads + 外呼） |
| 📣 市场投放 / 增长 `后续` | 渠道结构清晰、可生码、投放链接一键可得、归因可追 | 渠道管理 · 落地页 |
| 🎧 客服 / 用户支持 `后续` | 快速查到用户与订单、看清状态与有效期；后期单点触达答疑 | 用户中心 · 订单中心 ·（后期）触达/服务节点 |
| ⚙️ 管理员 / 系统配置 `后续` | 账号鉴权（限 `@dinoai.ai`）、业务线/模版配置、角色权限 | 系统配置 · 角色权限 |
| 🧑‍🏫 学习服务 / 班主任（后期） | 按生命周期节点拿到待办、对单用户触达与跟进、记录服务结果 | （后期）服务节点 · 单点触达 · 用户中心 |

## 打开方式

直接用浏览器打开 `index.html` 即可（无需构建）。也可部署到 GitHub Pages 后在线访问。
